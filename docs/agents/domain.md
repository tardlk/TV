# 领域文档

本仓库使用 single-context 布局。Gradle 多模块不自动视为多个业务上下文。

## 探索前读取

- 根目录 `GLOSSARY.md`：存在时读取，后续输出使用其中定义的领域术语。
- `docs/adr/`：存在时按当前改动领域读取相关 ADR。

不存在时静默继续；在具体术语确定或实际架构决策形成时，由 domain-modeling 按需创建。配置阶段不创建空术语表、空 ADR 或目录占位文件。

## 与现有项目规范的关系

- `AGENTS.md` 是本工程规范入口；当前实现范围见 `.scratch/android-tv/spec.md`，设计档案见 `.scratch/design/`。
- 现有产品规范继续留在原位置；glossary 只定义术语，ADR 只记录符合条件的架构决策。
- 历史接手与研究记录是日期快照，不作为覆盖当前用户目标或实现的依据。
- 用户已选定 TVBoxOS 为代码底座、AVBox 为视觉参考，并授权建立独立 TV 应用。HTML 是设计阶段快照，当前状态以 Android 规格与验证记录为准。

## 消费规则

- Issue 标题、规格、调试假设、测试命名和架构建议使用 glossary 的既定词汇。
- 概念尚未定义时，核对项目实际用语；确有缺口时交由 domain-modeling 明确。
- 提议与既有 ADR 冲突时，引用对应 ADR 并解释重开决策的理由。
- 既有规范与拟议变更冲突时，先明确冲突及适用范围，再按用户决定更新，不静默覆盖。
